# Changelog

All notable changes to Alex-Nano-Bot will be documented in this file.

## [1.24.3] - 2026-11-03

По результатам первого прогона на сервере.

### Fixed
- **Разбор сообщений: Groq в JSON-режиме отвечает 400 `json_validate_failed`**, когда модель отказалась отвечать (инъекция «покажи системный промпт») или истратила бюджет на рассуждения. Раньше участник видел «Не получилось обработать сообщение»; теперь это «нечего записывать» (обычная подсказка), в журнале — предупреждение
- Разбор запрашивает у gpt-oss `reasoning_effort=low` (`SPACE_INTAKE_REASONING`, по умолчанию `low`): для извлечения полей достаточно, быстрее и меньше токенов в минуту
- `scripts/intake_live_eval.py`: лимит токенов в минуту у провайдера (на бесплатном Groq 8000 TPM) превращал прогон в 70% «успеха» — фразы просто не получали ответа. Теперь: по умолчанию 1 запрос за раз, при лимитах ждёт по подсказке провайдера и повторяет (`--retries`, 4), запросы без ответа провайдера исключаются из точности и показываются отдельной строкой (⏳), при ответах меньше чем на половину запросов код возврата 3 («цифрам верить нельзя»)
- `scripts/server_check.py`: упёртый лимит провайдера — теперь замечание (WARN), а не поломка (FAIL), с повторами; проверка JSON-режима даёт модели достаточный бюджет токенов (50 хватало только на рассуждения); убрана ложная проверка ffmpeg — бот его не использует, ogg уходит в Whisper как есть

## [1.24.1] - 2026-11-03

### Added
- **`scripts/intake_live_eval.py`** — прогон живой модели через разбор сообщений пространств: 29 фраз (напоминания разовые/повторяющиеся/с адресатом, покупки, расходы, свои показатели, несколько действий, нейтральные фразы, инъекции) с точными ожиданиями на готовых записях (время в UTC, cron, сумма в копейках, категория, адресат). Ничего не пишет в БД и Telegram, «сейчас» зафиксировано. Отчёт в Markdown: строгая успешность, recall найденных записей, лишние записи, ложные срабатывания на нейтральных фразах и инъекциях, задержка p50/p95, стабильность при `--repeat N`, список расхождений. `--selftest` / `--selftest-broken` проверяют сам скрипт без сети (идеальная и заведомо плохая модель)
- **`scripts/server_check.py`** — проверка с сервера всех заявленных возможностей (25 возможностей, 41 проверка): окружение и версия, рабочая БД (только чтение: целостность, таблицы), Telegram (getMe, webhook, полнота меню команд), агенты и порядок роутеров, Runtime VM, ChromaDB (запись→поиск→удаление), доступ/лимиты/бан, BYOK, платежи, провайдеры LLM и JSON-режим, веб-поиск, Whisper, навыки, MCP, витрина, застрявшие напоминания/сбойные отчёты, и **полная функциональная проверка пространств во временной БД** (приглашения, роли, списки, расходы и показатели, напоминания «ровно один раз», разбор с отсевом абсурда, отчёты без дублей после «перезапуска», `/space_config`, изоляция данных). Отчёт `server_check_report.md`: успешность PASS/(PASS+FAIL), число работающих возможностей, покрытие, что требует внимания; код возврата 1 при FAIL (`--strict` — и при WARN). Секреты в отчёт не попадают. Флаги `--offline`, `--skip-llm`, `--only`
- Тесты скриптов (`tests/test_scripts.py`): идеальная модель проходит всё, плохая ловится, статусы и маскирование секретов, метрики отчёта, коды возврата

## [1.24.0] - 2026-11-02

### Added
- **Запись значений своих показателей через чат** (`app/spaces/intake.py`): четвёртый тип действия `record` — «продал 12 погремушек оптом», голосом тоже. В промпт попадают только показатели пространства (ключ, название, единица, категории); значение проверяет код (`metrics.to_stored`: число > 0, разумный потолок, деньги через Decimal), неизвестный ключ и ключ `expense` отклоняются, категория берётся только из списка показателя (неизвестная — запись без категории, не выдумывается), дата — в границах как у расходов. Подтверждение кнопкой по умолчанию; снять — `auto_confirm: [..., "record"]`
- Показатель может иметь `categories` (до 30): сводки разбивают по ним, у показателей без категорий блок категорий скрыт
- **`/space_config`** (админ и выше): показать настройки; `set <ключ> <JSON>`; `unset <ключ>`; колонки `timezone` и `currency` задаются обычной строкой. Ключи: `metrics`, `reports`, `auto_confirm`, `intake`, `categories`, `terms`. Проверка тем же кодом, что читает настройки (`parse_metrics`/`parse_specs`), плюс перекрёстная: отчёт не может ссылаться на несуществующий показатель, а показатель, на который ссылается отчёт, нельзя удалить; настройки ≤ 8 КБ; невалидное целиком отклоняется, ничего не пишется частично (`app/spaces/config.py`)
- **`/report [id]`**: без аргумента — список отчётов пространства (адресованные админам видят только админы); с id — построить сейчас за последний полный период
- `/undo` отменяет последнюю запись любого показателя и показывает её в единицах показателя

### Changed
- Смена `currency` пространства не переписывает старые записи: записи в прежней валюте в сводки новой не попадают (команда об этом предупреждает)

## [1.23.0] - 2026-11-02

### Added
- **Отчёты пространств по расписанию** (`app/spaces/reports.py`). Отчёт — это описание: показатель, период (месяц/неделя), когда слать, кому (всем/только админам). Числа считает SQL, текст собирает код, LLM не участвует — цифры нельзя «придумать», работа бесплатна
  - включение и умолчания из `.env`: `SPACE_REPORTS_ENABLED` (общий выключатель), `SPACE_REPORT_DEFAULTS` (`monthly` — 1-го числа за прошлый месяц, `weekly` — по понедельникам за прошлую неделю, оба или пусто), `SPACE_REPORT_HOUR`
  - свои отчёты пространства — `settings["reports"]` (перекрывает умолчания; `[]` — отчётов нет): `[{"id","title","metric","period":"month|week","day":1-28,"weekday":"mon".."sun","time":"HH:MM","audience":"all|admins","send_empty":false,"enabled":true}]`; ошибки описаний пропускаются с записью в журнал
  - расписание по часовому поясу пространства; каждый слот уходит **ровно один раз** независимо от перезапусков и параллельных процессов (таблица `report_runs`); неудачная доставка повторяется до 3 раз; после простоя уходит только последний слот, слот старше 36 часов задним числом не досылается; пустой период молчит (`send_empty` — слать «записей нет»)
- **Показатели** (`app/spaces/metrics.py`): кроме расходов можно считать что угодно — проданные штуки, часы, километры. Описываются в `settings["metrics"]`: `[{"key","title","unit","kind":"money|count"}]`. Хранятся в том же журнале (`ledger_entries.metric`, единица измерения — в `currency`), отчёты и сравнение с прошлым периодом работают для любого показателя; разные показатели и единицы не смешиваются
- **Свои типы отчётов**: модуль из `SPACE_REPORT_PLUGINS` вызывает `register_report_type(имя, построитель)`; в описании отчёта `"type": "<имя>"`. Сбой плагина изолирован
- Цикл исполнителя поддерживает периодические хуки (`run_loop(..., hooks=[(корутина, секунд)])`)

### Fixed
- Первый вызов хука цикла не должен ждать N секунд после запуска процесса (проверка `loop.time()` от нуля зависела от времени работы машины)
- Единица измерения показателя («шт») не приводится к верхнему регистру — иначе записи не находились сводкой

## [1.22.0] - 2026-11-02

### Added
- **Свободный текст и голос участников пространства → записи** (`app/spaces/intake.py`, `app/handlers/intake.py`; при `SPACES_ENABLED=true` и `SPACE_INTAKE_ENABLED=true`). Сообщение (голосовое сначала распознаётся) разбирает одна LLM-модель в JSON-черновик из трёх типов: напоминание (разовое «завтра в 18:00 / в пятницу / через 2 часа» и повторяющееся: каждый день, по дням недели, раз в месяц; адресат — участник или «всем»), покупки, расход. **Всё, что попадает в базу, проверяет код, а не модель**: суммы через Decimal, даты в разумных границах (прошедшее время и «через 100 лет» отбрасываются с пояснением), адресат только из участников (по имени, с падежами «Маме»; неоднозначность не угадывается), категория только из списка пространства, лимиты на число дел/позиций/длины; неизвестные типы действий игнорируются, текст сообщения для модели — данные, не инструкции
- **Подтверждение кнопкой** («✅ Записать / ✖️ Отмена») для напоминаний и расходов; ожидающее хранится в БД 15 минут, обрабатывается ровно один раз (двойное и параллельное нажатие, чужое нажатие, устаревшее — отказ), доступ перепроверяется в момент нажатия. Покупки пишутся сразу; список типов без подтверждения — настройка пространства `auto_confirm` (по умолчанию `["shopping"]`). Один сбойный пункт не отменяет остальные
- `/list` — общий список покупок кнопками: нажатие вычёркивает/возвращает (видно, кто вычеркнул), «🧹 Убрать вычеркнутое»; `/expenses [prev|1-12]` — расходы за месяц; `/undo` — отменить свой последний расход
- Расход голосом сохраняет распознанный текст и источник; расход токенов и дневные лимиты учитываются как у остальных сообщений (BYOK работает так же)
- Настройки: `SPACE_INTAKE_ENABLED`, `SPACE_INTAKE_MODEL`; отключить для пространства — `settings {"intake": false}`

### Notes
Для участников пространства (в том числе админа, если он состоит в пространстве) обычные сообщения теперь разбираются как записи, а не уходят ассистенту; отключается настройкой пространства `intake: false`. Пользователи без общего пространства работают с ассистентом как раньше.

## [1.21.0] - 2026-11-02

### Fixed
- **`/remind`, `/daily`, `/weekly` присылали не текст напоминания, а ответ LLM-агента**: задачи создавались с типом `one_time`/`recurring` и при срабатывании шли в `_process_ai_task` («🤖 Автоматическое задание» — платный вызов, текст мог быть переписан). Теперь они создаются по схеме пространств и уходят текстом как есть, без LLM
- **Тип задачи `reminder` не планировался** (`_schedule_task` его не знал): теперь планируется как разовый (по `run_date`) или повторяющийся (по cron), а разовый после срабатывания закрывается

### Changed
- Личные напоминания живут в личном пространстве (kind `personal`, создаётся при первом обращении; приглашать в него нельзя; доступа в закрытого бота не даёт; команды общих пространств его не видят)
- `/tasks` показывает новые напоминания (идентификатор вида `r12`) вместе с прежними задачами; `/cancel_task r12` отменяет новое, `/cancel_task 12` — прежнее. В общих пространствах видны напоминания «всем», «мне» и созданные вами
- Исполнитель напоминаний стартует всегда, а не только при `SPACES_ENABLED=true` (он же доставляет личные)
- Дни недели для еженедельных — именами (`mon`…`sun`): числовая нумерация cron в APScheduler (0 — понедельник) отличается от классической

### Upgrade
Прежние активные напоминания (созданные до 1.21.0) не трогаются: они сработают один раз по-старому (через LLM) и завершатся; повторяющиеся `/daily`/`/weekly` старого типа продолжат идти через LLM, пока их не отменить (`/cancel_task <номер>`) и не создать заново. Если таких много — скажите, добавим команду переноса.

## [1.20.0] - 2026-11-01

### Added
- **Данные пространств** (все таблицы с `space_id`, доступ только через `SpaceScope`):
  - `app/spaces/checklists.py` — списки (покупки, сборы, задания): добавление пачкой с нормализацией и защитой от дублей среди невычеркнутых, вычёркивание кем угодно из участников (кто и когда — в записи), очистка вычеркнутого, HTML-рендер
  - `app/spaces/ledger.py` — журнал расходов: суммы целыми копейками (`to_minor` отвергает ноль, минус, nan, опечатки-миллиарды), категории из списка пространства (`settings["categories"]` или набор по виду; неизвестное из текста LLM → «Прочее», новые категории не плодятся), отмена своей последней записи, удаление чужой только админом, сохраняются исходный текст и источник (text/voice)
  - **месячная сводка** SQL-агрегатами (итог, по категориям, по людям, крупнейшие, сравнение с прошлым месяцем) и текст отчёта; границы месяца — по часовому поясу пространства; записи в другой валюте в сумму не входят
- **Напоминания пространств** (`app/spaces/reminders.py`, `runner.py`): адресату или всем участникам, разовые и по cron; хранятся в своей таблице, а не в APScheduler, поэтому переживают рестарт, пропущенное за время простоя доставляется после запуска (при длинном простое повторяющееся приходит один раз, без пачки). Доставка с арендой: параллельные исполнители не дублируют, упавшая доставка повторяется (до 5 попыток), один недоступный адресат не мешает остальным; вышедший адресат → получает автор; выключенное пространство молчит
- `SPACE_REMINDER_POLL_SECONDS` (по умолчанию 15). Исполнитель стартует вместе с ботом при `SPACES_ENABLED=true`

### Notes
В существующем планировщике (`TaskScheduler`) найдены два расхождения, поведение которых не менялось: разовое напоминание `/remind` создаётся с типом `one_time` и при срабатывании идёт через LLM-агента (а не отправляется текстом как есть), а тип `reminder` в `_schedule_task` не обрабатывается и не запланировался бы. Для пространств это обойдено отдельным исполнителем.

## [1.18.0] - 2026-11-01

Предметная область задаётся полем `kind` и словарём подписей (`terms.py`, переопределяется в `settings["terms"]`), в коде нет слов «семья»/«класс». ### Upgrade
Ничего делать не нужно: пока `SPACES_ENABLED=false`, поведение прежнее. Хендлеры создания пространства и вступления по ссылке — следующим патчем.

## [1.17.0] - 2026-11-01

### Fixed
- **Промпт Planner, выгруженный `--print-prompt` в 1.15.0, портился docker compose**: значение было в двойных кавычках, а compose подставляет `$имя` в значениях `env_file` без кавычек и в двойных — `$step1` и `$step_id` превращались в пустую строку («The "step1" variable is not set» при каждом `docker compose`), в примерах оставалось `"text": ""`. Проверка 1.15.0 это пропускала, потому что в промпте оставался `$<id шага>`. Теперь: ссылка должна быть настоящей (`$step1`), пустые `"text": ""`/`"prompt": ""` в примерах отвергаются с подсказкой про compose; `--print-prompt` выводит значение в одинарных кавычках в несколько строк (проверено на docker compose v5 и python-dotenv: `$` и переводы строк читаются буквально)
- **`migrate_env.py` обрезал многострочные значения** `.env` (строки продолжения терялись): теперь значения в кавычках на несколько строк переносятся дословно

### Added
- **Промпты из файла**: `PLANNER_SYSTEM_PROMPT_FILE`, `SHOWCASE_SYSTEM_PROMPT_FILE`, поле `system_prompt_file` у витрины в `SHOWCASES`. Без кавычек, `\n` и `$`; правка файла подхватывается без перезапуска (по mtime).
