# Changelog

All notable changes to Alex-Nano-Bot will be documented in this file.

## [1.13.0] - 2026-10-30

### Added
- **Пакетная загрузка корпуса из .zip**: администратор присылает архив с `.md`/`.txt` в чат витрины (после `/corpus_upload`), документы попадают в корпус этой витрины. Имя документа — путь внутри архива (общая корневая папка срезается), одинаковые имена в разных папках не сливаются
- Подпись к архиву: **`dry`** — только проверка (что добавится, обновится, удалится; ничего не меняется); **`sync`** — дополнительно удалить из корпуса документы, которых нет в архиве. Синхронизация не удаляет прежние версии файлов, которые есть в архиве, но не прочитались, и отказывается работать, если в архиве нет ни одного документа
- **Идемпотентность**: документ с тем же именем и тем же содержимым (хэш сохраняется в метаданных чанков) пропускается; изменённый заменяется новой версией, старая удаляется только после успешного добавления; ошибка одного файла не останавливает пакет. Документы, загруженные до 1.13.0 (без хэша), один раз переиндексируются
- Прогресс индексации в одном обновляемом сообщении; итоговый отчёт: добавлено / обновлено / без изменений / удалено / пропущено с причинами. Один импорт на корпус одновременно
- Безопасность архива: чтение в памяти, без записи на диск; отклоняются пути с `..`, абсолютные и `C:\`, символические ссылки, файлы с паролем; служебные файлы (`.DS_Store`, `__MACOSX`, скрытые) игнорируются; лимиты на размер архива, суммарный и одиночный размер, число файлов (`CORPUS_ZIP_*`); кодировки UTF-8 (с BOM) и cp1251
- Эмбеддинги документа считаются одним переходом в поток, а не по чанку

## [1.12.0] - 2026-10-30

### Changed
- **Чанки корпуса урезаны под модель эмбеддингов**: MiniLM-L12 видит только первые 128 токенов (~400–500 символов), а чанки были по 1200 — две трети каждого фрагмента не влияли на поиск. Новые умолчания: `CORPUS_CHUNK_SIZE=450`, `CORPUS_CHUNK_OVERLAP=80`, `CORPUS_TOP_K=8`. Для моделей с окном 512 токенов (mpnet, E5) — 1200 / 200 / 5
- **Новый резчик**: делит по строкам → предложениям → словам, не режет посреди слова, каждый чанк ≤ лимита; наложение считается в символах и не вылезает за лимит. Явный `chunk_overlap=0` больше не подменяется настройкой

### Added
- **Повторная загрузка файла заменяет прежнюю версию** (по имени файла): новая версия добавляется первой, старые чанки удаляются только после успеха. Раньше каждая загрузка (у Telegram новый `file_id`) создавала дубль
- `/corpus_delete <имя файла>` — удалить документ из корпуса витрины
- `/corpus_stats` показывает документы, число чанков и среднюю длину чанка
- `migrate_env.py`: предупреждение, если `CORPUS_CHUNK_SIZE` > 600 при модели с окном 128 токенов

### Upgrade
Уже загруженные документы не перерезаются сами: задайте значения в `.env` и загрузите файлы заново (старые версии заменятся).

## [1.11.1] - 2026-10-30

### Fixed
- **«Бот печатает…» висел до 3 минут после ответа**: при пересланной ссылке (в базу знаний), ошибке YouTube или пустой расшифровке голоса обработчик делал `return` до `stop_typing`, и индикатор продолжал обновляться, а потом пропадал без ответа. Остановка теперь в `finally` на любом выходе; расход токенов этих веток тоже записывается
- **knowledge_base**: разбор статьи падал с «в ответе LLM нет JSON-объекта» — рассуждающая модель (gpt-oss) расходовала весь лимит 600 токенов на размышления. Теперь `reasoning_effort=low`, лимит 1500 токенов, JSON-режим Groq; при неудаче в лог попадают `finish_reason` и начало ответа
- Ответ «Статья добавлена» не показывает пустые разделы («Темы:», «Ключевые факты:»), а при неудаче разбора честно пишет, что теги и факты не извлечены

## [1.11.0] - 2026-10-30

### Added
- **`EMBEDDING_MODEL` теперь действует** (раньше модель была зашита в коде, а настройка и README вводили в заблуждение). Рекомендуется `intfloat/multilingual-e5-large` для русского; для E5 автоматически добавляются префиксы `query: ` / `passage: ` (без них качество поиска заметно ниже)
- **Автоматическая перестройка индексов** при смене модели: коллекции `memories`, `skills`, `conversations`, `corpus*` пересчитываются из сохранённых текстов. Новая коллекция строится под временным именем и подменяет старую только после полного заполнения — при сбое данные целы; прерванная подмена восстанавливается при следующем старте. Бот и витрина делят хранилище — межпроцессная блокировка не даёт перестраивать одновременно. Коллекции, построенные прежней версией, распознаются как «MiniLM-L12» (перестройка не нужна, пока модель не менялась)
- **`EMBEDDING_CACHE_DIR`** (`data/models`): кэш модели на томе — не скачивается заново при пересоздании контейнера. Токен HuggingFace — `HF_TOKEN` в `.env`
- **`PLANBOT_MAX_CALLS`** (по умолчанию 4): бюджет LLM-вызовов PlanBot (план + шаги + итог). 4 вызова — до 2 шагов — укладываются в бесплатный лимит Groq (8000 токенов/мин); 7 — расширенный режим для платного тарифа или другого провайдера. Лишние шаги, придуманные моделью, отбрасываются; ответ с ```json-обёрткой больше не ломает разбор плана

### Changed
- Предупреждение в логе, если модель эмбеддингов не мультиязычная
- Прежнее значение `all-MiniLM-L6-v2` (стояло в `.env.example`, но не читалось; модель английская) игнорируется — используется мультиязычная по умолчанию

Статьи сохранялись без тегов; в логе — «LLM extract failed: … unexpected keyword argument 'system'». Исправлено, разбор ответа устойчив к ```json-обёрткам

## [1.10.1] - 2026-10-29

### Fixed
- **SkillBot**: поиск навыков («найди навык …») падал с `AttributeError` — у `SkillLoader` не было `search_skills`. Добавлен поиск по имени, описанию, категории и командам (служебные слова «найди навык»/"search for" отбрасываются, выдача ранжируется по числу совпадений)
- **`add_usage_daily`**: если параллельная сессия успела создать строку суток между UPDATE и INSERT (актуально для не-SQLite СУБД), INSERT падал с `IntegrityError` и расход терялся. Теперь при конфликте расход прибавляется к уже созданной строке

### Added
- **`scripts/migrate_env.py`**: приводит серверный `.env` к раскладке `.env.example`, перенося ваши значения (токены, модели, промпты, ID) дословно; добавляет новые ключи со значениями по умолчанию, схлопывает дубли (действует последнее), берёт `APP_VERSION` из шаблона, проверяет промпты (`PLANNER_SYSTEM_PROMPT` без схемы DSL, `SHOWCASE_SYSTEM_PROMPT` без базы знаний). Исходный `.env` не меняет, значения в отчёт не выводит

### Changed
- **`.env.example`**: системные промпты — в двойных кавычках (только так `\n` превращается в перенос строки), добавлены предупреждения о том, что переменная заменяет встроенный промпт целиком
- **`RAG_MEMORIES`** (по умолчанию 10, как и было в коде): число воспоминаний в RAG-контексте Planner вынесено из жёсткого `n_memories=10` в настройку. Старые записи про «8» — история, фактическое значение всегда было 10

## [1.10.0] - 2026-10-29 (раздельные витрины)

### Added — Несколько витрин в одном процессе
- **`SHOWCASES`** (JSON): у каждой витрины свой бот (токен или `token_env`), коллекция знаний, режим доступа (`invite` по умолчанию / `open`), группа оператора, приветствие, промпт и модель. Эмбеддинг-модель, БД и LLM-клиент общие — новая витрина не требует отдельного контейнера. Без `SHOWCASES` — одна «наследная» витрина по прежним переменным (`SHOWCASE_BOT_TOKEN`, `OPERATOR_CHAT_ID`, `SHOWCASE_OPEN_ACCESS`, коллекция `corpus`)
- Витрина определяется по боту-получателю (middleware + `ContextVar`), а не по данным пользователя; при нескольких витринах отсутствие контекста — ошибка, а не тихий выбор первой
- Конфигурация проверяется при запуске: опечатки в ключах, неверный `slug`/токен/`access`, дубли slug/токена/коллекции — ошибка с понятным текстом; невалидный токен одной витрины пропускается, остальные работают
- `app/core/showcases.py` (реестр, контекст), `app/core/showcase_access.py` (участники и приглашения)

### Added — Доступ по приглашению
- `/invite [N] [дней]` — ссылка `t.me/<бот>?start=inv_<код>` (N человек, срок; `0` — без ограничения), `/invites`, `/revoke_invite`, `/allow <id>`, `/deny <id>`, `/members` (admin, в самой витрине)
- Приглашение действует только в своей витрине; код погашается атомарно (параллельные `/start` не превысят лимит); уже участник приглашение не расходует; забаненный не может вступить; при сбое БД закрытая витрина закрыта
- Меню команд администратора показывается только админам (scope чата)

### Changed
- **Корпус на витрину:** `search_corpus` / `add_corpus_document` / `delete_corpus_document` / `get_corpus_stats` принимают `corpus`; имя строго `corpus` или `corpus_<имя>` — служебные коллекции (`memories`, `skills`, `conversations`) недоступны; существующая коллекция `corpus` не переиндексируется
- **`operator_sessions`:** ключ `client_id` → `(tenant, client_id)`; на существующей БД SQLite таблица пересоздаётся автоматически (копирование → удаление старой → переименование, сбой в середине не теряет данные); открытые обращения без витрины передаются первой витрине списка. Тема в группе оператора ищется в пределах витрины — номера тем в разных группах совпадают
- Группа оператора, резюме (модель витрины), история диалога и антифлуд — на витрину; события `escalation.*` содержат `tenant`
- `APP_VERSION` 1.9.0 → 1.10.0; тесты 508 → **630**

### Fixed
- **Запуск падал на любой переменной в `.env`, которой нет среди полей настроек** (`extra_forbidden`, например `BOT_MEM_LIMIT` или токен второй витрины): настройки теперь игнорируют лишние ключи
- `.dockerignore`: `COPY . .` клал в образ `.env` с секретами, `.git`, `data/` и `logs/`

## [1.9.0] - 2026-10-28 (BYOK, кредиты и платежи, эскалация на оператора, экономия памяти)

### Added — Эскалация на оператора (витрина)
- **`/operator` и кнопка «Позвать оператора»** под каждым ответом витрины (раньше — только при «не нашёл»/ошибке): для клиента создаётся тема в супергруппе поддержки (`OPERATOR_CHAT_ID`), сообщения пересылаются в обе стороны, `/close` в теме или `/endchat` у клиента завершает обращение; лимит частоты обращений
- **Резюме для оператора**: в карточку темы попадает переписка клиента с ботом (раскрывающаяся цитата), следом — резюме от LLM (`app/core/handoff.py`, таймаут 20 с; при сбое остаётся только переписка). Резюме хранится в `operator_sessions.summary` — задел под веб-интерфейс
- `app/core/dialog.py` — короткая память диалога клиента с ботом (в памяти процесса, TTL 24 ч, LRU); `app/core/support_events.py` — события `escalation.opened/summary/closed` для будущих адаптеров
- `docs/support-bot-design.md` — проект отдельного бота поддержки на llm-nano-vm (программы с suspend-шагами, граница сессии инструментов, память клиента, RAG per-client, веб-интерфейс как второй адаптер)

### Added — Лимит и доступ витрины
- **`SHOWCASE_OPEN_ACCESS`** — витрина открыта для всех независимо от `BOT_OPEN_ACCESS` (основной бот остаётся приватным); не задан — наследует `BOT_OPEN_ACCESS`
- **`SHOWCASE_DAILY_LIMIT`** (по умолчанию 20, 0 — безлимит) — суточный лимит LLM-ответов на пользователя по UTC; вопросы без ответа в базе знаний лимит не тратят; админы не ограничены

### Added — BYOK
- Пользователи подключают свои API-ключи (`/byok set <провайдер> <ключ>`; groq, openrouter, anthropic, openai), ключи шифруются Fernet (`ENCRYPTION_KEY`); с ключом запросы идут только на него, суточные лимиты не применяются; `BYOK_ENABLED`

### Added — Кредиты и платежи
- Пакеты запросов сверх бесплатного суточного лимита: 1 кредит = 1 сообщение, списание атомарное, зачисление идемпотентно (`UNIQUE(provider, charge_id)`); админы и BYOK не списываются
- Провайдеры: Telegram Stars, ЮKassa, Stripe (`BILLING_PROVIDERS`, `CREDIT_PACKAGES`); команды `/buy`, `/balance`, `/paysupport`, админ: `/grant`, `/refund` (возврат отклоняется, если кредиты потрачены)

### Changed — Память
- **Эмбеддинг-модель грузится лениво** (при первом использовании) и выгружается после простоя (`EMBEDDING_IDLE_UNLOAD_SECONDS`, по умолчанию 600; `0` — грузить при старте): ~270 МиБ у бота и ~230 МиБ у витрины в простое вместо ~800 и ~440 МиБ
- Навык `validated_answer` использует общую модель вместо отдельной копии на каждый вызов
- Потолки памяти контейнеров: `BOT_MEM_LIMIT`, `SHOWCASE_MEM_LIMIT` (по умолчанию `1280m`) — причиной циклических рестартов был OOM хоста (две копии модели в разных процессах, нет swap)
- Таблицы расширений (BYOK, оператор, биллинг) на SQLite автоматически получают недостающие колонки при старте; ранее после обновления кода на существующей БД падало `no such column`
- `APP_VERSION` 1.8.0 → 1.9.0; тесты 290 → **508**

### Fixed
- **`ADMIN_IDS` и `KB_CHANNEL_IDS` из нескольких значений:** «123,456» (формат из README) и пустое значение роняли запуск `SettingsError` — `pydantic-settings` разбирал список как JSON раньше нашего валидатора. Теперь принимаются «1», «1,2», «[1,2]» и пусто; `.env.example` читается как есть (тест)
- Устаревшие конфигурации: класс `Config` настроек заменён на `model_config`, в `pytest.ini` задан `asyncio_default_fixture_loop_scope`
- **CI на pytest 9.2:** общие моки в `tests/conftest.py` теряли атрибуты после отката `monkeypatch` (`has no attribute 'ADMIN_IDS'`), 9 failed / 326 errors; теперь `SafeMock`
- Учёт расхода (`usage_daily`) не работал для пользователей, которые пишут только в витрину: строка `users` не создавалась — витрина теперь регистрирует пользователя (хранится только `telegram_id`)
- Длинные ответы витрины: клавиатура прикрепляется к последней части

## [1.8.0] - 2026-10-27 (витрина, MCP, SKILL.md, безопасность, модернизация зависимостей)

### Added — Витрина службы поддержки (отдельная точка входа)
- **`app/bot_showcase.py` + `app/handlers/showcase.py`**: демо-бот со своим токеном (`SHOWCASE_BOT_TOKEN`) отвечает клиентам строго по загруженному корпусу — чанки из отдельной коллекции ChromaDB, перечень источников, честный отказ при отсутствии данных
- Команды: `/start`, `/help`, `/corpus_stats`, `/corpus_upload` (загрузка `.md`/`.txt` документов, admin); запуск — `docker compose --profile showcase up -d showcase`

### Added — Внешние инструменты и навыки
- **MCP-клиент `app/core/mcp.py`** (SDK 1.x/2.x; stdio / Streamable HTTP): инструменты внешних серверов доступны VM как `call_tool <server>__<tool>`, Planner видит их список; `/mcp` (admin), конфиг `MCP_SERVERS`
- **Agent Skills (SKILL.md)**: инструкционные навыки открытого стандарта [agentskills.io](https://agentskills.io/specification) — папка в `skills/external/` или установка документом `.md` (admin), запуск из `/skills`

### Security
- **SSRF-защита `app/core/net_guard.py`**: `knowledge_base`/`site_monitor` не ходят на приватные адреса (localhost, RFC1918, 169.254.169.254); исключение — `ALLOW_PRIVATE_URLS=true`
- **Политика инструментов**: не-админам в Runtime VM доступен только allowlist `RUNTIME_USER_TOOLS`; `user_id` навыку подставляется из контекста VM, а не из ответа planner
- **Админ-гейт** на создание/редактирование/удаление Python-навыков и установку SKILL.md
